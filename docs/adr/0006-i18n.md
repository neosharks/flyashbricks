# 0006 — English + Hindi by cookie, not URL

**Status:** accepted

## Decision

next-intl without locale routing. The language is a per-device preference in
an `HttpOnly` cookie (falling back to `Accept-Language`), switched from the
header or the account page. Messages live in one JSON file per area per
language; English is the type reference, and a test fails if Hindi is missing
a key or changes a placeholder. Server Action errors are translated centrally,
so features return codes, not sentences. Devanagari gets its own self-hosted
font and extra line height.

## Consequences

This is a signed-in tool, so there is nothing to index per language, and a
link shared between a Hindi and an English user opens in each reader's own
language. Emails, which cannot know the reader's choice, are bilingual.
