# 0003 — A static CSP with no third-party origins

**Status:** accepted

## Context

A nonce-based CSP is stronger, but Next derives its nonce from a header on the
_request_, and rewriting request headers in `proxy.ts` drops `Set-Cookie` from
the handler underneath — which silently breaks sign-in (learned in the
reference project, ecombro ADR 0003).

## Decision

One static policy set in `proxy.ts`: `'self'` everywhere, `'unsafe-inline'`
for scripts and styles only because Next's bootstrap needs it, no third-party
origins at all (fonts are self-hosted by `next/font`, charts are plain SVG, no
analytics). `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'none'`.

## Consequences

The real XSS defence is React's escaping and the absence of
`dangerouslySetInnerHTML` outside the fixed theme script. Revisit if Next
gains a nonce mechanism that does not touch request headers.
