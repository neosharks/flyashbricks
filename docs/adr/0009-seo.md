# 0009 — A small public website per language; everything else noindex

**Status:** accepted (revised: one landing page grew into four pages)

## Context

The product is a private business tool, but it is meant to be offered to many
brick plants, so it needs to be findable and to explain itself — in English
and in Hindi.

## Decision

- A public website of four pages — home, features, security, contact — each at
  one English and one Hindi address: `/`, `/features`, `/security`, `/contact`
  and `/hi`, `/hi/features`, `/hi/security`, `/hi/contact`. The English home
  page is shown at `/` only to visitors without a session.
- `proxy.ts` rewrites each address to `/welcome/*` and fixes the language with
  a request header; `/welcome/*` itself 308-redirects to the public address so
  every page has exactly one address per language. The page list lives in
  `components/marketing/site.ts`.
- Each page has its own title, description and keywords in its language, a
  canonical URL, `hreflang` alternates (`en-IN`, `hi-IN`, `x-default`), Open
  Graph/Twitter cards with a generated share image (`app/opengraph-image.tsx`),
  and the home page has JSON-LD (`SoftwareApplication`, `FAQPage`).
- Product pictures are real screenshots of the app with demo data, captured by
  `pnpm screenshots` into `public/screenshots/<locale>/`, so the Hindi pages
  show the Hindi app.
- `robots.txt` allows only the website pages, the share image, the screenshots
  and the build assets needed to render them; `sitemap.xml` lists every page
  with its language alternates.
- Every other response carries `X-Robots-Tag: noindex, nofollow` (set in
  `proxy.ts`) as well as the root layout's `noindex` meta, so nothing private
  is indexed even if a link to it leaks.
- The pages are server-rendered with no third-party scripts or web fonts beyond
  the self-hosted ones, and the mobile menu is a plain `<details>`, for fast
  Core Web Vitals on phones.

## Consequences

Signed-in people still get the dashboard at `/`. Search engines and signed-out
visitors get the home page at the same address. Set `NEXT_PUBLIC_APP_URL` to
the real https domain before launch — canonical, sitemap and share-image URLs
are built from it. Re-run `pnpm screenshots` against a seeded copy after a
visible change to the app.
